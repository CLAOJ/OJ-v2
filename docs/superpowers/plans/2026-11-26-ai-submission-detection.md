# AI Submission Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an "AI submissions" tab to the admin plagiarism check that lists contestant × problem rows suspected of AI-written code, using three signals (match against AI reference solutions, wrong-answer rewrites, performance outlier).

**Architecture:** The existing contest plagiarism job (`claoj/jobs/moss.go`) gains a second compare50 run per problem × language that compares contestants against stored AI reference solutions (archive submissions), plus two Go-only signals computed from the DB. Everything is written to one `ai.json` in the contest report dir and swapped in with the reports. Reference solutions live in a new v2-only table, generated by the LLM from the statement or pasted by admins.

**Tech Stack:** Go (gin, gorm, asynq, testify, sqlite in tests), Python 3 compare50 fork (unittest), Next.js + react-query + next-intl, MariaDB.

**Spec:** `docs/superpowers/specs/2026-11-26-ai-submission-detection-design.md` (builds on `docs/superpowers/specs/2026-11-25-plagiarism-compare50-design.md`).

## Global Constraints

- Two repos: the fork at `f:\Coding\CLAOJ\compare50` (branch `claoj`, never `main`), mounted in OJ-v2 as submodule `claoj/plagiarism`. OJ-v2 work happens on branch `feat/ai-submission-detection`.
- Do not push either repo without asking the user first. The submodule bump (Task 2) needs the fork commit pushed to `github.com/CLAOJ/compare50` branch `claoj`; ask before pushing.
- v2-only tables: declared in `scripts/v2_runtime_tables.sql`, listed as RETAINED-V2 in `scripts/cleanup_v2_tables.sql`, no `judge_` prefix. v1 tables (`judge_contestmoss`, all `judge_*`) are never written.
- Permission for every new endpoint: the existing `contestForMoss` (`judge.moss_contest`), routes under `/admin/contest/:key/plagiarism`.
- LLM env reused: `COMPARE50_LLM_URL`, `COMPARE50_LLM_KEY`, `COMPARE50_LLM_MODEL`. Without all three, generation is skipped; everything else still runs.
- Only statement text and the language go to the LLM for generation; never usernames or contestant code.
- A failed LLM call or a missing statement never fails the run; it becomes a note in `ai.json`.
- "Failed run keeps the previous results": `ai.json` and the AI reports live inside the contest report dir that `RunContestMoss` already swaps atomically.
- Admin UI strings in both `claoj-web/src/i18n/en.json` and `vi.json`; the AI tab says rows are "for review, not proof".
- Starting thresholds (constants in `claoj/jobs/ai_detect.go`, tuned in Task 9):
  `aiRefsPerLang = 5`, `aiStatementMinChars = 300`, `aiMatchPct = 50`, `aiTrivialShare = 0.5`, `rewriteMaxSimilarity = 0.3`, `rewriteMinLines = 5`, `rewritesToFlag = 2`, `historyMargin = 1.5`.

## Review Focus

1. A contestant with only one submission, or whose best and first submissions are the same row, must produce one folder, no `~first` duplicate, and no S3 value (0 rewrites). Test in Task 6.
2. A problem × language where nobody matched and no references exist (PDF-only statement, LLM off) must still appear in `ai.json` `problems[]` with the note, and no rows. Test in Task 6.
3. Usernames that `SubmissionFolder` wraps (`~con~`) must map back to the right username in `ai.json` rows, including their `~first` folder. Test in Task 6.
4. An LLM reply with prose around the code, or a fence with a language tag (```` ```cpp ````), stores only the code. Test in Task 4.
5. Reference endpoints must refuse a problem that is not in the URL's contest (no cross-contest writes or deletes by id). Test in Task 7.

```go
type AIReport struct {
	GeneratedAt time.Time   `json:"generated_at"`
	Rows        []AIRow     `json:"rows"`
	Problems    []AIProblem `json:"problems"`
}
type AIRow struct {
	Username        string     `json:"username"`
	ProblemCode     string     `json:"problem_code"`
	Language        string     `json:"language"`
	BestSubmission  uint       `json:"best_submission_id"`
	FirstSubmission uint       `json:"first_submission_id"`
	Match           *AIMatch   `json:"ai_match"` // nil when no reference pair
	Rewrites        int        `json:"rewrites"`
	RewriteSubs     []uint     `json:"rewrite_submission_ids"` // the later attempt of each rewrite
	AboveHistory    *bool      `json:"above_history"`
	PrevMaxPoints   *float64   `json:"prev_max_points"`
	RatingBefore    *int       `json:"rating_before"`
	SpeedInversion  bool       `json:"speed_inversion"`
	Signals         int        `json:"signals"`
}
type AIMatch struct {
	Pct        int    `json:"pct"`
	ReportPath string `json:"report_path"` // "<problem>/<slug>/ai"
	MatchPage  int    `json:"match"`       // match_<n>.html
}
type AIProblem struct {
	ProblemCode string `json:"problem_code"`
	Language    string `json:"language"`
	Generated   int    `json:"generated"`
	Admin       int    `json:"admin"`
	Contestants int    `json:"contestants"`
	Matched     int    `json:"matched"` // contestants with Match.Pct >= aiMatchPct
	Trivial     bool   `json:"trivial"` // Contestants > 0 && Matched/Contestants >= aiTrivialShare
	Note        string `json:"note"`    // from EnsureReferences, or "no_references"
}
```

- Behaviour:
  - Extend the existing submissions query with `s.id`, `s.date`, `s.result`, `pr.id AS profile_id`, `part.id AS participation_id`, `part.start AS real_start`, `judge_problem.points`. Best per (language, user) stays as today. First = lowest `date`, then lowest `id`.
  - AI folders under `<tmp>/ai/<problem>/<slug>/subs/`: `SubmissionFolder(user)` holding the best, and `SubmissionFolder(user)+"~first"` holding the first, only when it is a different submission. References go to `<tmp>/ai/<problem>/<slug>/refs/ref_<id>/main.<ext>`. Run `chk.Check(ctx, subsDir, refsDir, <reportRoot>/<problem>/<slug>/ai)` only when there is ≥ 1 reference and ≥ 1 contestant. Read `results.json`: the non-archive side's folder → user (strip `~first`), `pct` = that side's `pct_*`; keep the best per user.
  - S3 chains: all of that participant's contest submissions for the problem in `date, id` order, split by language; `Rewrites` = sum of `CountRewrites` over the chains.
  - S4 queries, once per contest: previous max = `MAX(judge_problem.points)` over the user's `result = 'AC'` submissions with `date < contest.start_time` (any problem, in or out of contests); rating before = `judge_rating.rating` of the latest row with `last_rated < contest.start_time`. Both apply only to rows where the user has an AC on that problem in this contest.
  - Listing: S1 fires = `Match != nil && Match.Pct >= aiMatchPct && !problem.Trivial`; S3 fires = `Rewrites >= rewritesToFlag`; S4 fires = `AboveHistory == true || SpeedInversion`. List the row iff S1 or S3 fires. `Signals` = number of S1 (counting `Pct >= aiMatchPct` even on trivial problems), S3 and S4 that fired. Sort by `Signals` desc, then `Match.Pct` desc (nil = −1), then username.
  - Every problem × language that has submissions gets an `AIProblem`, including those with no references (`Note = "no_references"` when `EnsureReferences` returned `""` but there are zero references).
  - `ai.json` is written even when it has no rows.

**Interfaces:**
- Produces (all behind `auth.RequireContestEdit()` + `contestForMoss`):
  - `GET /admin/contest/:key/plagiarism/references` → `{"references": [{"id","problem_code","language","origin","model","source","created_at"}]}`, for the contest's problems only, ordered by contest problem order, then language, then id.

  - `DELETE /admin/contest/:key/plagiarism/references/:id` → 404 unless the reference's problem is in the contest.
